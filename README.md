## 1. Purpose
The `Backend` module serves as the primary FastAPI web application layer for the Nexus AI platform. It operates as a **thin routing layer**, capturing client requests and delegating core domain business logic, data models, and workflow actions to the shared [`common_lib`](../Python%20Libs/common_lib) package.

---

## 2. API Surface & Routing Architecture
All endpoint groups are mounted as modular routers in `app/modules/`:

- **`/api/v1/app_ops`**: Heartbeat check, system metrics, and execution status.
- **`/api/v1/auth` & `/api/v1/users`**: Authentication hooks (Argon2 ABAC + JWT tokens) and User CRUD.
- **`/api/v1/rbac`**: Roles, permissions, and tenancy scope check.
- **`/api/v1/workflows`**: DAG graph layout, state machines, and visual workflow executions.
- **`/api/v1/doc_processing`**: Multimodal document ingestion triggers.
- **`/api/v1/triggers`**: Cron timings and scheduler executions.

## 3. Local Stack & Running
* **Installation:** Run `uv sync` to set up the dev virtual environment.
* **Environment Configuration:** Override local credentials by placing a `.env` file in this directory (e.g., `DISABLE_AUTH=True` to bypass token checks in dev).
* **Database Services:** Spin up the PostgreSQL and PgAdmin containers using Docker:
  ```bash
  docker compose up -d
  ```
* **Database Seeding:** Initialize roles, default prompts, and workflows:
  ```bash
  uv run seed_db.py
  ```
* **Development Server (Watch Mode):** Start the server with watchfiles reload tracking changes:
  ```bash
  ./clean-start.sh
  ```

## 5. Alembic Migration Checklist
Always perform migrations manually to prevent massive autogenerated diff drops:
1. Ensure a single migration head exists:
   ```bash
   uv run alembic heads
   ```
2. Create a blank revision script:
   ```bash
   uv run alembic revision -m "feat(module): description_of_changes"
   ```
3. Edit the generated file in `alembic/versions/` to implement `upgrade()` and `downgrade()`.
4. Apply the migration:
   ```bash
   uv run alembic upgrade head
   ```
